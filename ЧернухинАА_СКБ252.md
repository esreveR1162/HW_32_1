## 2. Постановка задачи

  

Необходимо реализовать консольное приложение на C++ (стандарт C++11 и выше), моделирующее обработку задач несколькими потоками.

  

### Основные требования:

  

1. **Класс `TaskQueue`**:

- Хранит очередь целых чисел

- Является потокобезопасным

- Предоставляет методы добавления и извлечения задач

- Использует `std::mutex` и `std::condition_variable`

  

2. **Рабочие потоки (workers)**:

- Извлекают задачи из очереди

- Обрабатывают их (вывод на экран)

  

3. **Главный поток**:

- Добавляет в очередь числа от 1 до 20

- Запускает рабочие потоки

- Дожидается обработки всех задач

- Корректно завершает все потоки через `join()`

  

### Ограничения:

- Запрещено использование busy-wait (бесконечный цикл без ожидания)

- Запрещено использование сторонних библиотек

- Запрещено завершение программы без корректного завершения потоков

### 3.2 Потокобезопасная очередь

  

Потокобезопасность достигается за счет:

- **`std::mutex`** — защищает доступ к очереди, не позволяя нескольким потокам одновременно изменять её состояние

- **RAII-блокировки** (`std::lock_guard`, `std::unique_lock`) — гарантируют освобождение мьютекса даже при исключениях

  

```cpp

void add(int value) {

{

std::lock_guard<std::mutex> lock(mutex_);  // автоматическая блокировка

queue_.push(value);

}  // автоматическая разблокировка

cv_.notify_one();

}
```
### 3.3 Использование std::condition_variable

condition_variable позволяет потоку без активного ожидания (busy-wait) ждать появления задач в очереди.

Механизм работы:

```cpp 
bool try_pop(int& value) {

std::unique_lock<std::mutex> lock(mutex_);

// wait() атомарно:

// 1. разблокирует мьютекс

// 2. засыпает до notify

// 3. пробуждается и снова захватывает мьютекс

cv_.wait(lock, [this]() {

return !queue_.empty() || finished_;

});

if (!queue_.empty()) {

value = queue_.front();

queue_.pop();

return true;

}

return false;

}

```

### 3.4 Механизм корректного завершения потоков
```cpp
// Этап 1: Ожидание реального завершения работы

while (processedCount.load() < 20) {

std::this_thread::sleep_for(std::chrono::milliseconds(10));

}

  

// Этап 2: Сигнал потокам, что нужно завершиться

taskQueue.finish();  // устанавливает finished_ = true и notify_all

  

// Этап 3: Ожидание фактического завершения потоков

for (auto& t : workers) {

if (t.joinable()) {

t.join();

}

}
```
В методе finish():
```cpp
void finish() {

{

std::lock_guard<std::mutex> lock(mutex_);

finished_ = true; // флаг завершения

}

cv_.notify_all(); // пробуждаем ВСЕ ожидающие потоки

}
```
Когда рабочий поток просыпается и видит finished_ == true при пустой очереди, он выходит из цикла и завершается.

В ходе выполнения данной работы изучены основы многопоточности в языке C++. Освоено создание и управление потоками с помощью std::thread, синхронизация доступа к общим ресурсам с использованием std::mutex. Также изучено использование std::condition variable для организации эффективного ожидания без активного цикла. Это важно, потому что busy wait потребляет ресурсы процессора впустую.

Была реализована потокобезопасная очередь задач. Она позволяет нескольким потокам одновременно добавлять и извлекать задачи без ошибок. Это достигается за счет блокировки мьютекса при каждом обращении к очереди. Условная переменная позволяет рабочим потокам засыпать, когда очередь пуста, и просыпаться только когда появляется новая задача. Такой подход является эффективным и правильным.

Также освоено корректное завершение многопоточный программ. Это важно, потому что если просто завершить главный поток, рабочие потоки могут остаться висеть. Для корректного завершения использован специальный флаг finished и метод notify all. Это позволяет разбудить все потоки и дать им команду завершиться. После этого главный поток дожидается каждого рабочего потока с помощью join.
